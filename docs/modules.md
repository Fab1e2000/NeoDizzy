# iOS 模块与插槽

> 本文是实现说明。所有编码工作必须遵守根目录 [AGENTS.md](../AGENTS.md) 的最高架构约束；本文和历史实现记录不能作为降低模块解耦要求的依据。

## 当前边界与服务所有权

当前是同一应用 target 内的静态模块与能力注册机制，不是动态二进制插件，也尚未拆成独立 Swift Package。`AppComposition` 是唯一枚举内置平台的装配入口；`AppServices` 持有共享下载队列、播放器、播放解析器、离线资料库、喜欢、账号镜像、播放历史与资料库能力注册表，不再持有网易云或 DizzyLab 的具体账号服务。

- `PlatformRegistration` 提供模块描述、来源 ID 和 runtime 工厂；本地资料库不可停用，保证应用始终有可用入口。
- `PlatformRuntime` 持有模块及恢复、同步、关闭回调。平台在自己的 `NeteaseRuntime` / `DizzyLabRuntime` 中创建账号服务、注册能力并清理资源。宿主无需知道平台登录协议、收藏 API 或下载数据格式。
- `AppModule` 提供首页、目的页、可选账号/登录页、搜索分组、歌曲操作、歌单选择和集合操作。`ModuleRegistry` 按 ID 分发；没有注册的来源返回不可用，不尝试使用另一平台处理。
- `ModuleHost` 管理模块选择和每个插槽的导航路径。`ModuleSettings` 处理排序、隐藏和启动入口；平台集合变化时更新可用描述。旧标签迁移留在装配层。
- `AppRoute` 只携带模块 ID、可哈希目的地和标题。平台定义自己的路由载荷与集合路由映射。`AnyView` 仅用于模块与宿主之间的类型擦除边界。

所有平台复用同一播放器与视觉组件。DizzyLab 购买、社区和独立账号页仍属于平台功能；全局设置、下载队列和资料库不要求它的环境对象存在。宿主负责后台下载恢复，平台后台工作不能绑定在首页 `onAppear` 上。

连续播放由共享 `PlayerStore` 的 `AVQueuePlayer` 管理：提前解析并排入下一项，自然切换后交接播放历史、系统媒体信息与缓存，不重新清空播放器。顺序、随机、循环与注册的自动发现续播使用同一管线；DizzyLab 随便听听保留曲终暂停行为。平台只提供播放地址和续曲能力。队列调整、账号／音质变化和平台停用都会撤销或重建待播项；缓存清理同时保护当前与待播文件。

## 共享能力插槽

| 能力 | 共享入口 | 平台职责 |
| --- | --- | --- |
| 播放、歌词、音质与缓存身份 | `StreamResolver` 的来源注册 | 解析地址及有效期、试听状态、歌词、音质和会话缓存键；DizzyLab 也使用注册适配器 |
| 发现续播与播放上报 | `PlayerStore`、`PlaybackReportingSession` | 提供续曲和平台上报；宿主不直接调用某个平台 API |
| 下载 | `DownloadProvider`、`DownloadStore` | 计划、临时地址、文件处理、恢复迁移及显示摘要；共享队列不解码平台请求 |
| 喜欢 | `FavoritesProvider`、`FavoritesStore` | 提供账号、完整列表、写入操作；本机喜欢来源单独注册 |
| 账号歌单、专辑 | `AccountLibraryMirror` | 注册同步闭包；平台适配器映射为 `MirroredCollection`，通用存储按来源与账号隔离 |
| 导出、备份与恢复 | `LibraryProviderRegistry` | 提供集合歌曲读取、平台设置、可选凭据恢复和歌手头像；缺失能力保留不完整集合并标记原因 |
| 歌单选择、集合路由/取消收藏 | `AppModule`、`ModuleRegistry` | 平台提供页面和操作，统一资料库不持有平台 Store |
| 最近播放 | `PlaybackHistoryStore` | 注册集合身份映射；页面通过模块能力解析路由 |

账号镜像采用按 provider ID 保存的通用格式；旧 `account-mirror.json` 在独立迁移文件中转换，保留集合、首次添加时间与旧喜欢元数据。备份的新平台设置和凭据按 provider ID 存储，仍读取旧版 `neteaseQuality`、`neteaseCookie`。这些旧字段、旧曲目隐式来源及旧偏好 key 属于数据兼容，不是共享服务对平台实现类型的依赖。

## 隐藏、停用与移除

“隐藏模块”只隐藏导航入口，服务仍注册；不会删除账号、文件、队列，也不中断已提交的下载或支付核验。

“停用模块”由 `AppServices.setEnabled` 管理并持久化。宿主先撤销该平台的页面、喜欢、账号镜像、资料库导出、播放历史等能力，再清理播放、平台网络会话与下载任务。平台关闭回调取消自己的请求和工作；镜像及导出请求通过代次检查拒绝迟到结果，不能在停用后重新提交。其他平台的注册、数据和任务保留。

停用不等于退出账号或删除数据：已保存的音频和队列记录保留；账号镜像保留在磁盘，但未注册来源不出现在当前账号集合中。重新启用会重新创建 runtime、注册能力并恢复服务。当前正在播放的来源停用时，其在线播放由播放器的来源停用流程处理；本地文件仍按本地可用性解析。无法识别的旧来源不能回退到其他平台。

iOS 平台实现统一归属 `Core/Modules/<平台>` 与 `Features/Modules/<平台>`。DizzyLab 的网络、账号、购买、社区、模型和页面也包含在这两个目录内。发行配置移除模块时，删除这两处源码并移除 `AppComposition` 中对应的注册行；模块专项测试随模块移除，基座和保留模块的源码与测试继续完整保留。Xcode 工程中的模块文件归属同步清理。

模块只依赖基座契约与通用数据：`AppModule` 负责页面、账号与操作入口；`PlatformRegistration` 负责装配及可选旧下载迁移；`PlatformRuntime` 负责恢复、同步和停用。播放器、下载队列、离线库、搜索容器和设置不导入具体平台实现。`CoverCard`、`ExpandableText`、专辑布局等是基座视觉组件，平台不借用另一平台的页面或模型。

本地库及磁盘兼容迁移属于基座，不能随平台删除。`Track` 旧版隐式来源、账号镜像旧字段、网易云旧目录命名和旧标签偏好只处理本机历史数据，保留平台标识字符串不要求平台代码存在。应用视觉主题的 `DizzyPalette` 和 `DizzyGrid` 也是基座组件。

`scripts/check-module-boundaries.py` 扫描所有 iOS 基座和平台 Swift 文件；`scripts/test-module-removal.py` 在隔离副本中实际删除源码，运行所有保留测试并校验基座与保留模块的文件哈希。清单见 `scripts/module-removal-manifest.json`。矩阵为删除 DizzyLab、删除网易云、删除 QQ 音乐、删除全部平台（保留本地库）；完整结果见[源码删除验证报告](testing/module-removal-2026-10-23.md)。macOS 的旧界面装配不包含在这套 iOS 验收中。

## 接入 QQ 音乐或其他平台

1. 确定稳定的模块 ID 与 provider ID，例如 `qqmusic`；定义自己的 `Hashable` 路由载荷。歌曲映射为 `Track.remoteSource(providerID:itemID:)`，不把临时签名地址放入持久队列。
2. 在平台目录实现网络客户端、账号 Store、业务 API 与页面。会话和凭据独立保存；账号变化使旧请求、页面缓存和播放资源失效。
3. 实现 `AppModule`，提供首页、搜索、路由与可选账号/歌曲/歌单能力。复用 `AlbumTrackRow`、专辑头部、网格和播放器，不复制共享样式。
4. 实现平台 runtime 工厂，将播放、下载、喜欢、账号镜像、导出恢复等实际支持的能力注册进宿主；不支持的能力不注册。平台关闭回调必须阻止新请求、取消任务并 await 完整关闭事务，包括外层回滚及持久化收尾。
5. 生产装配仅在 `AppComposition.registrations` 加入注册项；同时扩展边界检查、模块归属清单和物理删除矩阵。共享页面、播放器和下载调度不增加平台 switch。系统后台恢复由宿主与 runtime 生命周期承担。
6. 验证单个平台、本地资料库及多平台组合：账号切换、旧请求迟到、停用/启用、缺失来源、离线文件、下载队列与旧数据恢复。必须按根规范运行全量边界检查及删除工具安全自测，在隔离副本中逐一删除各平台、删除全部在线平台并运行所有保留测试，核对实际装配集合与保留文件完整性。

`LibraryProviderIsolationTests` 覆盖镜像来源隔离、停用期间迟到结果、旧格式迁移、缺失来源导出和平台设置/凭据分发；通过测试不代表真实账号接口或真机后台行为已验收。

## 历史平台功能与实现记录

下述内容记录现有平台能力和历次实现验证；平台装配、服务所有权与停用行为以以上当前边界为准。

## 网易云音乐

`NeteaseModule` 按同一插槽接口注册，支持隐藏、排序和设为启动页面。首页沿用 DizzyLab 的页头、双列入口与封面网格；提供推荐歌单、新碟、歌曲/专辑/歌单搜索、排行榜、每日推荐、私人 FM 和我的歌单。歌单曲目每批加载 100 首，其余分页内容每批 30 项；私人 FM 首页卡片直接进入播放器；每批歌曲按顺序播放，余量不足时预取下一组并在歌曲结束后续播。

协议参考 [MeloX 的原生网络实现](https://github.com/youshen2/MeloX/blob/1fe5fbab3f554e8529c4847fc54281a472b7b61a/MeloX/Core/Networking/NeteaseDirectClient.swift) 和同版本 NeteaseAPI、NeteaseAPI+Home、NeteaseLoginView（GPL-3.0）。采用 eapi AES-ECB 封装与官方网页登录，无需部署第三方 API 服务。登录页使用独立临时 WebKit 数据存储，用户完成官网登录后点“完成”，验证账号并把 MUSIC_U / __csrf 存入独立钥匙串条目。请求不使用全局 Cookie 容器。

`Track.remoteSource` 保存 providerID/itemID，队列 ID 使用 remote/provider/item 命名空间；旧队列字段缺省时仍按 DizzyLab 解析。`StreamResolver.register` 接收来源的播放地址和歌词解析器，缓存依据过期时间、曲目和来源会话变化失效；未知来源不能回退到 DizzyLab。无权限歌曲显示不可播放，试听按服务端 freeTrialInfo 标记。网易云账号切换不会清除 DizzyLab 缓存，反之亦然。

本轮接入的是 iOS 模块界面；macOS 保持原有导航。会员歌曲、每日推荐、私人 FM、个人歌单及收藏写操作需要用户自行登录验证；网易云音频下载由共享下载队列处理，未加入额外音源替换。

个人主页切换内容分段时保留用户资料，返回已加载分段时不重新请求。社区网页会话与音频 API token 分开判断；缺少用户导航标记时以同一会话的首页核验身份，不把解析缺失直接当作退出登录。账号页内部请求登录时由该弹层就地呈现登录页。滚动标题随系统下拉运动，不再用逐帧反向 offset 补偿。

跨模块视觉组件以 DizzyLab 为基准复用：DiscoverSearchBar、DiscoveryCategoryPicker、ModuleShortcutCard、CoverCard，以及 AlbumDetailScrollView / AlbumHero / AlbumPlaybackActions / AlbumTrackRow。网易云专辑、歌单、每日推荐使用同一专辑式布局，私人 FM 直接进入播放器；搜索歌曲也复用曲目行。平台只提供文案、数据、路由和操作，不独立复制控件样式。曲目行支持独立显示序号，歌曲来源 ID 不参与 UI 编号。

## 内容与封面预热

两个网络模块均在模块生命周期内保留页面模型，进入首页后按需预热入口首屏，不做定时轮询或整库抓取。封面预热每个列表最多前 12 张，模块内工作队列每批最多 3 张；共享 AlbumArtworkPreload 同时准备详情封面、背景色、常用网格和头像的解码规格。

网易云列表数据提前为详情页提供标题和封面；歌单先显示头部，再补齐曲目，服务端已返回完整首批曲目时不重复请求。并发进入同一页面复用在途任务，账号切换丢弃页面缓存和预热任务。DizzyLab 的首页、社团、关注、已购数据由模块持有，专辑详情复用模型（最多保留 40 个）及列表封面；账号或购买状态变化时废弃详情缓存。随便听听入口本身无远程封面，取歌仍由用户的播放操作触发。

DizzyLab 的随便听听卡片也直接获取歌曲并展开播放器，不再经过介绍页面。两个入口共用防重复点击、取消和失败重试交互。FM 缓冲队列随账号变更清理；切换到普通专辑时，旧的续曲请求不能覆盖当前播放。

## 发现播放预缓冲

私人 FM 与随便听听共用 PlayerStore 的单曲预取槽。当前曲目完成地址解析并交给播放器后，获取下一首及其播放地址，以静音 AVPlayer 在 readyToPlay 后执行 preroll；预缓冲项目建议前向缓冲 8 秒，实际数据量由 AVFoundation 决定。点击下一首复用同一在途任务及已预缓冲的播放器（两个固定播放器共用系统媒体会话，切换时重绑进度观察），不重复取歌或取流。未准备好时等待，失败保留当前曲目并允许重试，不承诺弱网下零延迟。此机制针对下一首，首次进入卡片仍需要取得首曲。

每次只保留一首预缓冲音频，不下载整组 FM，不做定时请求。返回上一首、启动新播放会话、切换普通专辑或账号变更时废弃旧预取。签名地址接近过期或预缓冲项目失败时回退到正常解析；DizzyLab 购买后废弃预取以免继续使用试听资源。FM 原有自动续播、DizzyLab 原有曲终停播行为不变。

## 网易云发现与账号资料库扩展

参考 MeloX `1fe5fbab3f554e8529c4847fc54281a472b7b61a` 的 `NeteaseAPI.swift`、`NeteaseAPI+Home.swift`、`NeteaseAPI+AlbumSubscriptions.swift`、`NeteaseDirectClient.swift` 和首页资源模型（GPL-3.0）。复用其官方服务端路径、EAPI 参数、WEAPI AES-CBC/RSA 封装、首页资源映射及空响应兼容路径；不依赖代理 API 服务器。WEAPI 只转发本模块的 MUSIC_U/__csrf，并使用本地随机设备标识。

### NCM 下载处理

网易云下载接口接受 `ncm` 类型，仍拒绝试听片段。下载完成后由 `NeteaseDownloadedAudio` 检查 `CTENFDAM` 文件头，即使接口声明为 FLAC 也会识别实际 NCM 容器。参考 [taurusxin/ncmdump 的 ncmcrypt.cpp](https://github.com/taurusxin/ncmdump/blob/4ede4cee1bad35bbf28a7b5524feeca0422a4feb/src/ncmcrypt.cpp) 中的容器布局、AES-ECB 密钥解包和字节掩码算法，以 Swift / CommonCrypto 独立实现：后台按 64 KiB 分块解密，检查字段长度、密钥前缀、填充和音频头，并支持取消与失败清理。

这是还原原始音频，不是转码：FLAC 保存为 `.flac`，MP3 保存为 `.mp3`。容器内的元数据与封面区跳过，继续使用现有下载流程从 API 写入曲目信息、封面及歌词，并以实际扩展名生成离线清单；普通音频保持原有格式。支持经典 NCM 容器，其他加密版本返回错误，不尝试猜测格式。

测试样本由 `scripts/generate-ncm-fixtures.py` 用项目已有静音音频生成，不包含商业歌曲或账号数据。`NeteaseDownloadedAudioTests` 检查逐字节还原、跨块边界、错误格式声明、普通音频、截断/损坏和取消；`NeteaseDownloadTests` 检查 NCM 下载源与标签/清单衔接。真实服务端 NCM 与真机下载仍需验证。

### 状态、性能及边界

- `NeteaseLibrary` 是账号级的单一状态源。所有写入成功后才更新 UI，按对象合并重复点击；喜欢列表、我的歌单和专辑分别保留版本，旧读请求不能覆盖新写入。账号变化同时使网络响应及资料库任务失效。
- 我创建的歌单不能取消收藏；“加入歌单”只列出当前账号创建且非“我喜欢的音乐”的歌单。接口明确返回 512 时才执行 MeloX 的双 ID 兼容重试；超时、空响应等不确定写入不自动重试。
- 共用 `AppModule.songActions` 插槽提供播放器按钮，播放器不直接持有网易云收藏状态。普通歌曲列表继续复用 `AlbumTrackRow`，额外菜单由模块注入；所有歌曲集合继续沿用 DizzyLab 专辑布局。
- 首页固定展示精选，移除首页分类选择器及热门歌手、新歌推荐、猜你喜欢分区；搜索结果保留类型选择。首页分区独立加载，保留旧内容，失败局部重试。只将已支持的歌单、歌曲资源映射为原生入口，不执行服务端任意 action 字符串。图片预热沿用每列表首批 12 张、每批 3 张的队列。
- 我喜欢的音乐每页 100 首；分类歌单、新碟、歌手专辑每页 30 条；精品歌单使用 lasttime 游标并去重。个人歌单按 MeloX 取最多 2000 条元数据，避免错误的分页空响应覆盖有效首批。
- 这里的最近播放入口读取网易云账号的服务端记录；当前平台播放上报由独立 reporter 接入共享上报注册表。尚未覆盖播客、云盘上传、消息、一起听、识曲等独立子系统；不把接口声明数量当成功能验收。

### 验证记录

新增及相关测试共 27 项通过，覆盖真实加密请求体、写入失败、重复提交、账号隔离、旧读取竞态、喜欢列表分页、精品游标及首页资源映射。公开只读实测：分类歌单、精品歌单、新歌推荐、新歌速递、相似歌曲返回 code=200；热门歌手连接在当前运行环境返回 curl 56 / HTTP 400，未取得有效数据。收藏与喜欢使用隔离 HTTP 桩验证，未操作用户真实账号；登录后的服务端写入、设备上的布局和触感待用户验收。未进行模拟器点击操作。

### 网易云下载的目录与本地分类

专辑下载直接使用专辑名作为文件夹名。扫描会将旧下载器生成的「作者 - 专辑名」目录改为专辑名，并同步修正 M3U 引用；自定义名称和已有同名目标不覆盖。

歌单下载按歌单身份合并到 `歌单/歌单名`，清单的来源类型为 `playlist`。歌单原封面独立保存在清单中，本地列表、详情和预览优先使用该封面，不再从第一首歌曲取图；旧清单可从保留的下载请求恢复原封面。文件名使用歌单顺序和歌曲 ID，避免跨专辑同名歌曲冲突，音频标签仍保留原专辑信息。去重只检查目标歌单，其他专辑已有的歌曲不会导致跳过歌单文件。扫描持续索引音频供播放和标签编辑使用，但只在本地歌单页展示，不在专辑页新增；每首提交完成后即可看到已下载内容。旧 M3U 中同一歌曲的专辑引用优先替换为歌单目录里的文件。删除下载歌单会删除其目录内的下载音频，其他专辑的副本保留；手建引用歌单仍只删除列表。

### 网易云收藏操作校验与 405 排查

用户确认此前的“官方 App”是 MeloX 发行版，并非网易云官方客户端。下载目录安装包标识为 `moye.MeloX`，版本 `2.0 (9110201)`。不能据此认定网易云官方客户端也失败，或将问题归因于账号限制。

MeloX 已有同类报告：https://github.com/youshen2/MeloX/issues/16 。api-enhanced 也记录了 v2/v3 校验方式不稳定：https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/issues/270 。这些报告证明问题值得复现，不证明具体根因。

官网当前 core 脚本 `core_c7686f506f6f2607bb7f6cea1951f039.js` 中 `playlist_fav-add` 只提交 id，统一请求层补 csrf_token，并将 /api/ 改为 /weapi/、方法改为 POST。基于这个直接来源，当前候选实现把歌单收藏/取消收藏切换为 WEAPI，不再请求 Watchman token，也不在失败后切换协议或重试。其他接口保持原状。

此前的 Watchman 提供器仍可供显式 requiresCheckToken 请求使用，但“获得非空 token”不证明业务接口接受该 token。HTTP 状态与业务码分开显示，405 或空响应不提交本地收藏状态。

回归测试使用隔离 HTTP 桩；真实收藏成功必须在手机操作后读回“我的歌单”确认。当前 WEAPI 方案属于待设备验证的候选修复，不应以测试通过代替服务端成功，也尚未对上游宣称修复完成。

### 下载并发调度

设置中的「下载 → 并行下载数量」支持 1～6 个文件，默认 2，跨任务共用网络槽位并持久化。获取链接也预占槽位，避免并发超限。音频解密、标签写入与入库使用独立处理队列（最多两个任务同时处理、同任务按序提交），不占下载槽位。降低并行数不会中断已开始的文件；新文件等槽位释放后按新上限启动。任务完成等待所有传输与处理结束，取消/删除同时停止两条队列，删除会等写入退出后再清理暂存文件。

## 统一「喜欢」资料库

`FavoritesStore` 是喜欢状态的本地读取入口，`favorites.sqlite` 按来源和账号保存歌曲快照。记录身份为平台 ID + 平台歌曲 ID；同名歌曲不跨平台去重。未登录的平台不展示其他账号缓存；本地与 DizzyLab 喜欢保存于独立的本机范围。

`FavoritesProvider` 只负责提供当前账号、读取完整喜欢列表、设置歌曲喜欢状态。当前注册网易云和 QQ 音乐；酷狗和汽水尚未接入。网易云首页不再显示独立的喜欢快捷入口；保留“我的歌单”中的原始“我喜欢的音乐”。资料库同步定位当前账号创建的 `specialType == 5` 歌单，读取其详情中的完整 `trackIds`，按原顺序分批补充歌曲详情；缺失歌单或读取不完整时保留旧数据；写入走 `NeteaseLibrary.setSongLiked`，服务端成功后才提交本地 SQLite。失败保留已确认的数据，界面提供错误和重试。刷新期间发生喜欢操作时，旧读取结果作废并重读。

iOS 资料库首页的分类方块里有固定的「喜欢」入口，空列表也保留；歌单页不再放「喜欢」。平台自带喜欢歌单不再作为另一个在线歌单出现在资料库；平台自己的页面仍可访问。歌曲行、搜索结果和播放器统一使用 `FavoriteButton`。本地与 DizzyLab 操作只改本机记录，不触发购买、下载或平台收藏。

启动、回到前台、账号变化、资料库下拉、喜欢页下拉都会同步；不会定时轮询。旧账号镜像的喜欢缓存仅在对应数据库范围不存在时导入一次，已经清空的数据库不会被旧缓存恢复。账号镜像现在负责歌单、专辑和艺术家元数据，不再驱动统一喜欢列表；歌单和专辑各自提交同步结果。

验证：`FavoritesTests` 覆盖跨平台重复、来源内去重、SQLite 重启恢复、失败保留、账号隔离、旧读取与写入竞态、一次性迁移。模拟器验证播放器喜欢、歌单取消喜欢和不可删除的空入口。真实网易云账号写入仍需设备验收。

### 喜欢详情与资料库导出

「喜欢」复用 `AlbumDetailScrollView` / `AlbumHero`，封面取统一列表第一首歌曲的封面；该歌曲没有封面时使用占位图，不沿用上一首封面。喜欢记录新增可选 `addedAt`，兼容旧数据库。各来源内部始终保留平台列表顺序，跨来源只比较各列表首项的加入时间进行合并；本机新喜欢直接插到第一位，刷新不按标题、曲号或内嵌标签排序。初次同步没有平台时间戳时，使用本机首次同步时间，并保留返回次序。

设置「音乐库」分组中的「导出资料库配置」生成版本化 JSON（`format: NeoDizzyLibrary`、`version: 1`），通过系统文件导出器保存。内容包括当前可见的喜欢列表、手动保存的歌曲、本地专辑／歌单、在线专辑／歌单及歌曲元数据。在线集合在用户发起导出时逐个读取完整歌曲列表；失败保留集合并标记 `songsComplete: false` 与 `issue`，界面告知不完整集合数量。分享导出的配置不包含音频、播放地址、封面缓存路径、登录凭据或其他账号缓存。当前已支持合并恢复与本机自动备份；本机备份可选择包含已注册平台的登录凭据，分享导出仍不带凭据，导入不会直接改写平台收藏。


### 歌曲收藏操作统一入口

歌曲列表的 `SongLibraryActions` 提供「喜欢／取消喜欢」「加入歌单」，由 `AlbumTrackRow` 和 `LibrarySongRow` 接入；喜欢、本地歌单／专辑、网易云各列表、DizzyLab 专辑、资料库歌曲／歌手／搜索因此共享相同行为。播放器保留 UIKit 菜单触摸行为，复用 `FavoriteButton` 和 `songPlaylistSheet`。`SongPlaylistDestination` 统一选择写入位置：网易云歌曲（包括下载副本）写账号歌单；其他有本地文件的歌曲写本地 M3U8；无可用接口且未下载时解释限制，不打开必定失败的本地选择器。平台特有的下载、歌手、专辑跳转仍由各模块补充。

DizzyLab 歌曲不再提供单独「加入资料库」动作；启动时将旧 saved-items 歌曲记录合并到本机喜欢，保留加入时间与既有喜欢，迁移标记与新列表在 SQLite 同一事务提交，成功后才清理旧文件。标记确保清理失败或旧文件再次出现时不会复活已取消的喜欢。专辑／歌单仍使用「加入资料库／从资料库移除」，保持各平台账号收藏与本机收藏的既有语义。

网易云首页移除「我的歌单」「收藏专辑」「最近播放」入口；前两类由统一资料库访问，歌曲加入账号歌单的选择窗口继续保留。

## 听歌缓存与统一音质

`AudioPlaybackCache` 管理 `Caches/ListeningAudio` 中的完整音频，默认上限 2 GiB，按最近播放/使用时间淘汰。`ProgressiveAudioLoader` 通过 AVAssetResourceLoader 将同一次 HTTP 传输写入磁盘并供播放器读取；不会为缓存再请求一次音频，也不会把整首歌曲堆进内存。实现结构参考 [CachingPlayerItem](https://github.com/neekeetab/CachingPlayerItem)，采用磁盘暂存和有界分块读取。

- 完整响应通过状态码、内容类型、字节数检查后才进入持久索引；未知长度响应要求传输正常结束。单个传输最多 512 MiB。错误页、截断响应和试听片段不会作为完整歌曲缓存。启动时清理无索引残留文件。
- 缓存键包含来源曲目 ID、登录会话摘要和所选音质，另存实际返回音质。索引不保存 Cookie 或签名 URL。同账号重新登录导致会话变化时会保守地重新缓存；手动下载的本地文件不受会话缓存范围影响。
- 下次播放先检查符合音质的手动下载及完整缓存，再解析在线地址；网易云播放、缓存、下载共用一个音质选项。升级沿用之前 Wi-Fi 音质，新安装默认高品质。服务端降级时保留所选与实际音质，修改选择后不会无条件命中旧设置的文件。排队中的显式下载保留入队时的音质。
- 切歌时实际可听播放时间严格大于曲目时长的 90% 才允许未完成传输继续，暂停/缓冲/拖动不增加计时。最多保留两个离开歌曲的下载；未达到门槛取消未完成传输。已经完整下载的文件不会因为早切歌而删除。不保证系统强制终止 App 后继续传输。
- 网易云手动下载可复用完整缓存并通过原有标签、歌词与本地音乐库提交流程保存，成功后去掉自动缓存副本。DizzyLab 的显式下载仍是官方专辑 ZIP，不用单曲串流缓存拼装或替代整张专辑包。
- iOS 设置与 macOS 播放设置中提供缓存占用和清理。清理取消离开歌曲的任务、阻止清理前的在途任务重新写回索引；当前播放器仍可读正在使用的文件，切歌后释放。手动下载、音乐库文件不受影响。占用显示完整缓存文件，不包含当前传输的暂存文件。
- 顺序下载支持从已接收区间即时读取；跳转到尚未收到的位置需要等待下载抵达该位置。请求合并、Range 分段续传不在本次实现范围。

## QQ 音乐

`Core/Modules/QQMusic` 按 [L-1124/QQMusicApi](https://github.com/L-1124/QQMusicApi) 的 Web 请求协议提供原生 Swift 适配，来源提交和许可证见 `THIRD_PARTY_NOTICES.md`。无需配置或部署 Python 服务。

- 支持推荐歌单、官方分组榜单、分类搜索及分页、单曲／专辑／歌单／歌手详情、多档音质播放和翻译歌词。歌曲访问权限遵循上游实际返回；空播放地址报错，不替换为试听片段。
- QQ 标签页沿用网易云的分区标题、横向封面列表和查看全部导航：推荐歌单来自 `PlaylistSquare.GetRecommendFeed`，榜单保留 `Toplist.GetAll` 的官方分组和顺序。封面复用基座 `CoverCard`，普通字号宽 156、无障碍字号宽 220；加载占位保持同样尺寸，刷新期间保留内容。搜索统一从搜索标签页进入。推荐歌单列表按响应 `FromLimit` 继续加载，重复游标或无新增条目时停止。页面缓存在 QQ 模块内，切换标签页／返回列表复用内容；首页与完整列表共享同一在途首屏请求，离开单个页面不会中断共享加载。账号变化及停用清空缓存、取消请求并使旧响应失效。
- 顶部提供「猜你喜欢」与「每日30首」双入口，下方为雷达推荐、歌单和榜单。「猜你喜欢」使用 `MbTrackRadioSvr.get_radio_track`，由 QQ 独立会话按批补歌、预取一批、去重并串行消费；重复或空批最多尝试三次，失败可重试。账号变化或停用会重置会话，迟到的首次推荐也不能覆盖用户后来暂停、切歌等播放操作。
- 「每日30首」使用 `DissInfo.CgiGetDiss` 的账号目录 `dirid=202`，沿用现有网页登录凭据，无需新增 API Key；未登录时引导登录。成功结果按请求日缓存，跨日进入或返回前台时重新加载，失败保留旧内容及过期状态。雷达使用 `TrackRelationServer.GetRadarSong` 的 `Page`／`HasMore` 分页，保持独立名称和数据来源。
- 设置中的 QQ 音乐账号入口与网易云一致，使用独立的非持久 `WebPage` 打开 QQ 音乐官网，扫码／其他登录选项由官网提供。用户完成网页授权后点击「完成」，模块最多读取 8 次 Cookie（间隔 400 毫秒），连续两次得到相同音乐凭据才发起一次在线验证；验证成功才更新账号并写入独立 Keychain 项。账号、音乐授权、身份字段未同步和服务器验证失败分别提示，可在原网页登录页重试。未完成授权、网络失败或关闭页面不会覆盖现有登录状态。没有自动续期；登录过期需重新在官网授权。账号资料库、下载和音质能力见下方对齐说明。
- Cookie 按固定 `https://y.qq.com/` 的有效域、路径和到期时间筛选，允许该 URL 可共同发送的父域和页面域字段组合，忽略登录域、无关子域及其他路径的 Cookie。同名／别名凭据冲突时等待同步，不按枚举顺序选账号。官网微信登录的 `W_X` 音乐密钥优先匹配 `wxuin`，可回退到音乐专用 `qqmusic_uin`；通用 QQ `uin` 不覆盖微信账号。19 位账号 ID 全程以字符串保存和请求，避免数值精度丢失。
- `QQMusicModule.registration` 是装配入口，宿主只在 `AppComposition` 增加注册。播放、歌词、历史和统一搜索均通过已有接口接入，未引用 DizzyLab 或网易云服务。停用会立即撤销页面与播放器能力、取消两个网络客户端的在途请求，保留 Keychain 凭据供重新启用。
- 听歌缓存按 QQ 平台、账号、凭据摘要和音质隔离。退出或重新登录会使旧在线地址失效，网页登录检查取消／页面退出／模块停用后，迟到的验证请求不能继续登录或更新页面。
- 账号提交串行完成网络客户端采用、Store 发布与 Keychain 保存；若提交期间取消或被新登录取代，按采用标记恢复尚未发布的账号，避免恢复操作覆盖较新凭据。新登录等待已经开始的退出操作完成，授权失败不会撤销用户的退出。
- 平台收藏、账号歌单选择与下载均注册到宿主的能力接口。QQ 收藏只在服务端确认成功后更新状态，未登录时引导现有官方网页登录。

验证分为确定性协议／隔离测试与真实网络验证。公共推荐歌单、搜索、榜单、专辑、歌单和歌词已收到有效响应；模拟器已显示推荐歌单与官方榜单分组，并可进入歌单和榜单曲目页；游客播放请求返回登录限制。2026-10-23 在用户手机上沿用现有登录只读验证：每日目录返回 30 首并全部解析成功，猜你喜欢返回 5 首且首曲获得完整 MP3_128 播放地址；这不等同于整批歌曲及长时间连续播放的听音验收。临时探测入口已移除。原生 QQ 二维码流程已移除，当前由官网负责生成二维码和授权。模拟器已验证设置入口、官网加载、QQ 扫码二维码显示，以及未登录点击「完成」的提示；用户扫码确认授权和登录后的会员／完整播放仍需使用真实 QQ 账号在设备上验收。

网页登录机制参考了 [Beans Music 的 iOS 手动同步流程](https://github.com/XIaodou0416/Beans-Music/blob/f9881318caf774129205c3160510ef0dfa318adc/Beans/QQWebLoginSheet.swift#L72-L114)、[Kunyin 的目标 URL Cookie 读取](https://github.com/ikunshare/kunyin-desktop/blob/5200df8867b0abae3d5402f64bee512de813d0de/src/main/auth/login/qqWeb.ts#L43-L66) 和 [Mineradio 的账号／音乐授权阶段区分](https://github.com/XxHuberrr/Mineradio-paused/blob/d43de565acabfdc1a9c9820a27e81a98ccbebcef/desktop/main.js#L2372-L2425)，以 Swift 独立实现。线上验证和业务请求仍使用 QQMusicApi 的四字段 Cookie 与 `W_X → tmeLoginType=1` 契约，不将网页的 `login_type` 数值直接用作 API 类型，也不把资料接口的 `code=1000` 当作验证成功。

每日30首请求参数另参考 [LX Flow Music 的 Web 实现](https://github.com/eohh-zhou/lx-flow-music-desktop/blob/14e254c733789cb1749f006b9da3a34e49fa3032/src/main/modules/winMain/rendererEvent/qqMusic.ts#L476-L502)，使用原生 Swift 与现有 QQ 网络客户端实现，未改动全局认证协议。

| 能力 | QQ 音乐实现 |

分类搜索沿用 QQMusicApi 的 `DoSearchForQQMusicMobile`，请求信封参考 Simple Music：module 作为键且不附 `comm`，其他接口认证协议不变。账号列表先从现有官网登录同源的 profile 接口读取 `encrypt_uin`，目录 ID、歌单 TID、歌曲 MID／数字 ID、专辑 MID／数字 ID 分别保存，不混用。完整读取须满足平台总数和继续标志，缺页、隐藏数据、重复页或解析错误保留旧快照。账号发布窗口内的请求也绑定预期账号，旧请求不能落到新账号。

下载按 `qqmusic/专辑` 或 `qqmusic/歌单` 存放，新目录加稳定集合 ID 避免同名冲突。音质更换采用宿主显式 `.updatingCollection` 能力，在暂存目录验证后原子替换同一歌曲，保留其他文件；原有模块的合并行为不变。试听、加密文件、格式不符和过期账号任务不能入库。
