# iOS 模块与插槽

> 本文是实现说明。所有编码工作必须遵守根目录 [AGENTS.md](../AGENTS.md) 的最高架构约束；本文和历史实现记录不能作为降低模块解耦要求的依据。

## 边界

`AppComposition` 是内置模块的装配入口。`RootView`、`ModuleRegistry`、`ModuleHost` 和 `ModuleSettings` 是宿主插槽，不导入具体模块页面，也不匹配平台 ID。所有模块共享现有播放器和视觉组件。

- `AppModule` 提供模块描述、首页、路由目的页、可选账号入口、环境/生命周期包装和外部 URL 处理。
- `ModuleRegistry` 验证非空、唯一的模块 ID，按 ID 分发页面，不按注册顺序试探路由。未知或缺失模块显示不可用页面。
- `ModuleHost` 管理选中的模块与每个插槽自己的导航路径。
- `ModuleSettings` 根据注入的描述保存顺序、显示状态和启动模块，不含 DizzyLab 的特例。旧版标签页的迁移位于装配层。
- `AppRoute` 只携带模块 ID、可哈希的目的地和显示标题；`DizzyLabRoute` 与 `LocalLibraryRoute` 各自定义目的地类型。旧链接通过模块文件中的工厂方法兼容。

`DizzyLabModule` 提供首页、平台路由和独立账号页。全局齿轮只打开应用设置；模块通过可选 `accountEntry`、`openAccount()` 与 `dismissAccount()` 提供和管理头像入口。没有账号能力的模块不显示头像。App 不再提供「音乐文件夹」页面：用户直接在「文件 › 我的 iPhone › NeoDizzy」放入音乐，或从其他 App「用 NeoDizzy 打开」；回到前台和资料库下拉时重新扫描。其环境包装负责登录、支付回调后的页面呈现、前后台订单核验和账号变化。`DizzyLabServices` 持有账号、购买、下载与浏览历史；后台恢复仍由应用服务装配层启动，不依赖打开某个标签页。

## 接入另一个模块

1. 分配不会随显示名称改变的 `ModuleID`，定义自己的 `Hashable` 路由载荷。
2. 实现 `AppModule`，通过 `destination(for:)` 校验载荷类型并返回目的页。
3. 生产装配仅在 `AppComposition` 注册模块及所需服务；同时扩展边界检查、模块归属清单和物理删除矩阵。插槽和设置页面不得新增平台 switch 分支。
4. 有登录或平台回调时，由模块自己的 `install(in:)` 包装环境与生命周期，`handleURL` 只接受自身 URL。通过 `ModuleHost` 请求切换页面。
5. 系统后台恢复属于服务生命周期；不要把它绑在首页的 `onAppear` 上。停用必须先阻止新请求、取消任务并 await 完整关闭事务，包括外层回滚及持久化收尾。
6. 按根规范执行全量边界检查、删除工具安全自测和隔离副本的物理删除矩阵，逐一删除各平台及删除全部在线平台；完整保留基座、本地库和其余平台的源码与测试，核对实际装配集合和保留文件完整性。

`AnyView` 仅用在模块与插槽之间的类型擦除边界，模块内部仍使用普通 SwiftUI 视图。

## 当前范围

这是同一应用 target 内的模块接口与注册机制，不是动态加载二进制插件，也尚未拆成独立 Swift Package。DizzyLab 与网易云音乐分别提供网络服务、账号和页面；共享播放器通过来源注册解析播放地址与歌词。

「隐藏模块」保持原有含义：隐藏标签入口，不删除账号、本地文件或正在播放的队列，不中断已提交的下载及支付核验。已隐藏模块的支付返回仍由该模块核验；没有注册的模块则没有 UI 路由或 URL 处理器。

macOS 保持现有侧栏结构，并兼容新的路由载荷；此次插槽 UI 改造适用于 iOS。

## 网易云音乐

`NeteaseModule` 按同一插槽接口注册，支持隐藏、排序和设为启动页面。首页沿用 DizzyLab 的页头、双列入口与封面网格；提供推荐歌单、新碟、歌曲/专辑/歌单搜索、排行榜、每日推荐、私人 FM 和我的歌单。歌单曲目每批加载 100 首，其余分页内容每批 30 项；私人 FM 首页卡片直接进入播放器；每批歌曲按顺序播放，余量不足时预取下一组并在歌曲结束后续播。

协议参考 [MeloX 的原生网络实现](https://github.com/youshen2/MeloX/blob/1fe5fbab3f554e8529c4847fc54281a472b7b61a/MeloX/Core/Networking/NeteaseDirectClient.swift) 和同版本 NeteaseAPI、NeteaseAPI+Home、NeteaseLoginView（GPL-3.0）。采用 eapi AES-ECB 封装与官方网页登录，无需部署第三方 API 服务。登录页使用独立临时 WebKit 数据存储，用户完成官网登录后点“完成”，验证账号并把 MUSIC_U / __csrf 存入独立钥匙串条目。请求不使用全局 Cookie 容器。

`Track.remoteSource` 保存 providerID/itemID，队列 ID 使用 remote/provider/item 命名空间；旧队列字段缺省时仍按 DizzyLab 解析。`StreamResolver.register` 接收来源的播放地址和歌词解析器，缓存依据过期时间、曲目和来源会话变化失效；未知来源不能回退到 DizzyLab。无权限歌曲显示不可播放，试听按服务端 freeTrialInfo 标记。网易云账号切换不会清除 DizzyLab 缓存，反之亦然。

本轮接入的是 iOS 模块界面；macOS 保持原有导航。会员歌曲、每日推荐、私人 FM、个人歌单及收藏写操作需要用户自行登录验证；网易云音频下载由共享下载队列处理，未加入额外音源替换。

个人主页切换内容分段时保留用户资料，返回已加载分段时不重新请求。社区网页会话与音频 API token 分开判断；缺少用户导航标记时以同一会话的首页核验身份，不把解析缺失直接当作退出登录。账号页内部请求登录时由该弹层就地呈现登录页。滚动标题随系统下拉运动，不再用逐帧反向 offset 补偿。

跨模块视觉组件以 DizzyLab 为基准复用：DiscoverSearchBar、DiscoveryCategoryPicker、ModuleShortcutCard、DiscCard，以及 AlbumDetailScrollView / AlbumHero / AlbumPlaybackActions / AlbumTrackRow。网易云专辑、歌单、每日推荐使用同一专辑式布局，私人 FM 直接进入播放器；搜索歌曲也复用曲目行。平台只提供文案、数据、路由和操作，不独立复制控件样式。曲目行支持独立显示序号，歌曲来源 ID 不参与 UI 编号。

## 内容与封面预热

两个网络模块均在模块生命周期内保留页面模型，进入首页后按需预热入口首屏，不做定时轮询或整库抓取。封面预热每个列表最多前 12 张，模块内工作队列每批最多 3 张；共享 AlbumArtworkPreload 同时准备详情封面、背景色、常用网格和头像的解码规格。

网易云列表数据提前为详情页提供标题和封面；歌单先显示头部，再补齐曲目，服务端已返回完整首批曲目时不重复请求。并发进入同一页面复用在途任务，账号切换丢弃页面缓存和预热任务。DizzyLab 的首页、社团、关注、已购数据由模块持有，专辑详情复用模型（最多保留 40 个）及列表封面；账号或购买状态变化时废弃详情缓存。随便听听入口本身无远程封面，取歌仍由用户的播放操作触发。

DizzyLab 的随便听听卡片也直接获取歌曲并展开播放器，不再经过介绍页面。两个入口共用防重复点击、取消和失败重试交互。FM 缓冲队列随账号变更清理；切换到普通专辑时，旧的续曲请求不能覆盖当前播放。

## 发现播放预缓冲

私人 FM 与随便听听共用 PlayerStore 的单曲预取槽。当前曲目完成地址解析并交给播放器后，获取下一首及其播放地址，以静音 AVPlayer 在 readyToPlay 后执行 preroll；预缓冲项目建议前向缓冲 8 秒，实际数据量由 AVFoundation 决定。点击下一首复用同一在途任务及已预缓冲的播放器（两个固定播放器共用系统媒体会话，切换时重绑进度观察），不重复取歌或取流。未准备好时等待，失败保留当前曲目并允许重试，不承诺弱网下零延迟。此机制针对下一首，首次进入卡片仍需要取得首曲。

每次只保留一首预缓冲音频，不下载整组 FM，不做定时请求。返回上一首、启动新播放会话、切换普通专辑或账号变更时废弃旧预取。签名地址接近过期或预缓冲项目失败时回退到正常解析；DizzyLab 购买后废弃预取以免继续使用试听资源。FM 原有自动续播、DizzyLab 原有曲终停播行为不变。

## 网易云发现与账号资料库扩展

参考 MeloX `1fe5fbab3f554e8529c4847fc54281a472b7b61a` 的 `NeteaseAPI.swift`、`NeteaseAPI+Home.swift`、`NeteaseAPI+AlbumSubscriptions.swift`、`NeteaseDirectClient.swift` 和首页资源模型（GPL-3.0）。复用其官方服务端路径、EAPI 参数、WEAPI AES-CBC/RSA 封装、首页资源映射及空响应兼容路径；不依赖代理 API 服务器。WEAPI 只转发本模块的 MUSIC_U/__csrf，并使用本地随机设备标识。

### NCM 下载处理

网易云下载接口接受 `ncm` 类型，仍拒绝试听片段。下载完成后由 `NeteaseDownloadedAudio` 检查 `CTENFDAM` 文件头，即使接口声明为 FLAC 也会识别实际 NCM 容器。参考 [taurusxin/ncmdump 的 ncmcrypt.cpp](https://github.com/taurusxin/ncmdump/blob/4ede4cee1bad35bbf28a7b5524feeca0422a4feb/src/ncmcrypt.cpp) 中的容器布局、AES-ECB 密钥解包和字节掩码算法，以 Swift / CommonCrypto 独立实现：后台按 64 KiB 分块解密，检查字段长度、密钥前缀、填充和音频头，并支持取消与失败清理。

这是还原原始音频，不是转码：FLAC 保存为 `.flac`，MP3 保存为 `.mp3`。容器内的元数据与封面区跳过，继续使用现有下载流程从 API 写入曲目信息、封面及歌词，并以实际扩展名生成离线清单；普通音频保持原有格式。支持经典 NCM 容器，其他加密版本返回错误，不尝试猜测格式。

测试样本由 `scripts/generate-ncm-fixtures.py` 用项目已有静音音频生成，不包含商业歌曲或账号数据。`NeteaseDownloadedAudioTests` 检查逐字节还原、跨块边界、错误格式声明、普通音频、截断/损坏和取消；`NeteaseDownloadTests` 检查 NCM 下载源与标签/清单衔接。真实服务端 NCM 与真机下载仍需验证。

### 状态、性能及边界

- `NeteaseLibrary` 是账号级的单一状态源。所有写入成功后才更新 UI，按对象合并重复点击；喜欢列表、我的歌单和专辑分别保留版本，旧读请求不能覆盖新写入。账号变化同时使网络响应及资料库任务失效。
- 我创建的歌单不能取消收藏；“加入歌单”只列出当前账号创建且非“我喜欢的音乐”的歌单。接口明确返回 512 时才执行 MeloX 的双 ID 兼容重试；超时、空响应等不确定写入不自动重试。
- 共用 `AppModule.songActions` 插槽提供播放器按钮，播放器不直接持有网易云收藏状态。普通歌曲列表继续复用 `AlbumTrackRow`，额外菜单由模块注入；所有歌曲集合继续沿用 DizzyLab 专辑布局。
- 首页固定展示精选，移除首页分类选择器及热门歌手、新歌推荐、猜你喜欢分区；搜索结果保留类型选择。首页分区独立加载，保留旧内容，失败局部重试。只将已支持的歌单、歌曲资源映射为原生入口，不执行服务端任意 action 字符串。图片预热沿用每列表首批 12 张、每批 3 张的队列。
- 我喜欢的音乐每页 100 首；分类歌单、新碟、歌手专辑每页 30 条；精品歌单使用 lasttime 游标并去重。个人歌单按 MeloX 取最多 2000 条元数据，避免错误的分页空响应覆盖有效首批。
- 最近播放读取网易云账号的服务端记录，未增加本应用播放上报。尚未覆盖播客、云盘上传、消息、一起听、识曲等独立子系统；不把接口声明数量当成功能验收。

### 验证记录

新增及相关测试共 27 项通过，覆盖真实加密请求体、写入失败、重复提交、账号隔离、旧读取竞态、喜欢列表分页、精品游标及首页资源映射。公开只读实测：分类歌单、精品歌单、新歌推荐、新歌速递、相似歌曲返回 code=200；热门歌手连接在当前运行环境返回 curl 56 / HTTP 400，未取得有效数据。收藏与喜欢使用隔离 HTTP 桩验证，未操作用户真实账号；登录后的服务端写入、设备上的布局和触感待用户验收。未进行模拟器点击操作。

### 网易云下载的目录与本地分类

专辑下载直接使用专辑名作为文件夹名。扫描会将旧下载器生成的「作者 - 专辑名」目录改为专辑名，并同步修正 M3U 引用；自定义名称和已有同名目标不覆盖。

歌单下载按歌单身份合并到 `歌单/歌单名`，清单的来源类型为 `playlist`。歌单原封面独立保存在清单中，本地列表、详情和预览优先使用该封面，不再从第一首歌曲取图；旧清单可从保留的下载请求恢复原封面。文件名使用歌单顺序和歌曲 ID，避免跨专辑同名歌曲冲突，音频标签仍保留原专辑信息。去重只检查目标歌单，其他专辑已有的歌曲不会导致跳过歌单文件。扫描持续索引音频供播放和标签编辑使用，但只在本地歌单页展示，不在专辑页新增；每首提交完成后即可看到已下载内容。旧 M3U 中同一歌曲的专辑引用优先替换为歌单目录里的文件。删除下载歌单会删除其目录内的下载音频，其他专辑的副本保留；手建引用歌单仍只删除列表。

### 网易云收藏操作校验与 405 排查

用户确认此前的“官方 App”是 MeloX 发行版，并非网易云官方客户端。下载目录安装包标识为 `moye.MeloX`，版本 `2.0 (9110201)`。不能据此认定网易云官方客户端也失败，或将问题归因于账号限制。

MeloX 已有同类报告：https://github.com/youshen2/MeloX/issues/16 。api-enhanced 也记录了 v2/v3 校验方式不稳定：https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/issues/270 。这些报告证明问题值得复现，不证明具体根因。

官网当前 core 脚本 `core_c7686f506f6f2607bb7f6cea1951f039.js` 中 `playlist_fav-add` 只提交 id，统一请求层补 csrf_token，并将 /api/ 改为 /weapi/、方法改为 POST。基于这个直接来源，当前候选实现把歌单收藏/取消收藏切换为 WEAPI，不再请求 Watchman token，也不在失败后切换协议或重试。其他接口保持原状。

此前的 Watchman 提供器仍可供显式 requiresCheckToken 请求使用，但“获得非空 token”不证明业务接口接受该 token。HTTP 状态与业务码分开显示，405 或空响应不提交本地收藏状态。

回归测试使用隔离 HTTP 桩；真实收藏成功必须在手机操作后读回“我的歌单”确认。当前 WEAPI 方案属于待设备验证的候选修复，不应以测试通过代替服务端成功，也尚未对上游宣称修复完成。

### 下载并发调度

设置中的「下载 → 并行下载数量」支持 1～6 个文件，默认 2，跨任务共用网络槽位并持久化。获取链接也预占槽位，避免并发超限。音频解密、标签写入与入库使用独立处理队列（最多两个任务同时处理、同任务按序提交），不占下载槽位。降低并行数不会中断已开始的文件；新文件等槽位释放后按新上限启动。任务完成等待所有传输与处理结束，取消/删除同时停止两条队列，删除会等写入退出后再清理暂存文件。

## 统一「喜欢」资料库

`FavoritesStore` 是喜欢状态的本地读取入口，`favorites.sqlite` 按来源和账号保存歌曲快照。记录身份为平台 ID + 平台歌曲 ID；同名歌曲不跨平台去重。未登录的平台不展示其他账号缓存；本地与 DizzyLab 喜欢保存于独立的本机范围。

`FavoritesProvider` 只负责提供当前账号、读取完整喜欢列表、设置歌曲喜欢状态。当前注册网易云；QQ、酷狗和汽水尚未接入。网易云首页不再显示独立的喜欢快捷入口；保留“我的歌单”中的原始“我喜欢的音乐”。资料库同步定位当前账号创建的 `specialType == 5` 歌单，读取其详情中的完整 `trackIds`，按原顺序分批补充歌曲详情；缺失歌单或读取不完整时保留旧数据；写入走 `NeteaseLibrary.setSongLiked`，服务端成功后才提交本地 SQLite。失败保留已确认的数据，界面提供错误和重试。刷新期间发生喜欢操作时，旧读取结果作废并重读。

iOS 资料库首页的分类方块里有固定的「喜欢」入口，空列表也保留；歌单页不再放「喜欢」。平台自带喜欢歌单不再作为另一个在线歌单出现在资料库；平台自己的页面仍可访问。歌曲行、搜索结果和播放器统一使用 `FavoriteButton`。本地与 DizzyLab 操作只改本机记录，不触发购买、下载或平台收藏。

启动、回到前台、账号变化、资料库下拉、喜欢页下拉都会同步；不会定时轮询。旧账号镜像的喜欢缓存仅在对应数据库范围不存在时导入一次，已经清空的数据库不会被旧缓存恢复。账号镜像现在负责歌单、专辑和艺术家元数据，不再驱动统一喜欢列表；歌单和专辑各自提交同步结果。

验证：`FavoritesTests` 覆盖跨平台重复、来源内去重、SQLite 重启恢复、失败保留、账号隔离、旧读取与写入竞态、一次性迁移。模拟器验证播放器喜欢、歌单取消喜欢和不可删除的空入口。真实网易云账号写入仍需设备验收。

### 喜欢详情与资料库导出

「喜欢」复用 `AlbumDetailScrollView` / `AlbumHero`，封面取统一列表第一首歌曲的封面；该歌曲没有封面时使用占位图，不沿用上一首封面。喜欢记录新增可选 `addedAt`，兼容旧数据库。各来源内部始终保留平台列表顺序，跨来源只比较各列表首项的加入时间进行合并；本机新喜欢直接插到第一位，刷新不按标题、曲号或内嵌标签排序。初次同步没有平台时间戳时，使用本机首次同步时间，并保留返回次序。

设置「音乐库」分组中的「导出资料库配置」生成版本化 JSON（`format: NeoDizzyLibrary`、`version: 1`），通过系统文件导出器保存。内容包括当前可见的喜欢列表、手动保存的歌曲、本地专辑／歌单、在线专辑／歌单及歌曲元数据。在线集合在用户发起导出时逐个读取完整歌曲列表；失败保留集合并标记 `songsComplete: false` 与 `issue`，界面告知不完整集合数量。配置不包含音频、播放地址、封面缓存路径、登录凭据或其他账号缓存；本轮仅支持导出，不自动导入或改写平台收藏。


### 歌曲收藏操作统一入口

歌曲列表的 `SongLibraryActions` 提供「喜欢／取消喜欢」「加入歌单」，由 `AlbumTrackRow` 和 `LibrarySongRow` 接入；喜欢、本地歌单／专辑、网易云各列表、DizzyLab 专辑、资料库歌曲／歌手／搜索因此共享相同行为。播放器保留 UIKit 菜单触摸行为，复用 `FavoriteButton` 和 `songPlaylistSheet`。`SongPlaylistDestination` 统一选择写入位置：网易云歌曲（包括下载副本）写账号歌单；其他有本地文件的歌曲写本地 M3U8；无可用接口且未下载时解释限制，不打开必定失败的本地选择器。平台特有的下载、歌手、专辑跳转仍由各模块补充。

DizzyLab 歌曲不再提供单独「加入资料库」动作；启动时将旧 saved-items 歌曲记录合并到本机喜欢，保留加入时间与既有喜欢，迁移标记与新列表在 SQLite 同一事务提交，成功后才清理旧文件。标记确保清理失败或旧文件再次出现时不会复活已取消的喜欢。专辑／歌单仍使用「加入资料库／从资料库移除」，保持各平台账号收藏与本机收藏的既有语义。

网易云首页移除「我的歌单」「收藏专辑」「最近播放」入口；前两类由统一资料库访问，歌曲加入账号歌单的选择窗口继续保留。

## 听歌缓存与统一音质

`AudioPlaybackCache` 管理 `Caches/ListeningAudio` 中的完整音频，默认上限 2 GiB，按最近播放/使用时间淘汰。`ProgressiveAudioLoader` 通过 AVAssetResourceLoader 将同一次 HTTP 传输写入磁盘并供播放器读取；不会为缓存再请求一次音频，也不会把整首歌曲堆进内存。实现结构参考 [CachingPlayerItem](https://github.com/neekeetab/CachingPlayerItem)，采用磁盘暂存和有界分块读取。

- 完整响应通过状态码、内容类型、字节数检查后才进入持久索引；未知长度响应要求传输正常结束。单个传输最多 512 MiB。错误页、截断响应和试听片段不会作为完整歌曲缓存。启动时清理无索引残留文件。
- 缓存键包含来源曲目 ID、登录会话摘要和所选音质，另存实际返回音质。索引不保存 Cookie 或签名 URL。同账号重新登录导致会话变化时会保守地重新缓存；手动下载的本地文件不受会话缓存范围影响。
- 下次播放先检查符合音质的手动下载及完整缓存，再解析在线地址；网易云播放、缓存、下载共用一个音质选项。升级沿用之前 Wi-Fi 音质，新安装默认高品质。服务端降级时保留所选与实际音质，修改选择后不会无条件命中旧设置的文件。排队中的显式下载保留入队时的音质。
- 切歌时实际可听播放时间严格大于曲目时长的 90% 才允许未完成传输继续，暂停/缓冲/拖动不增加计时。最多保留两个离开歌曲的下载；未达到门槛取消未完成传输。已经完整下载的文件不会因为早切歌而删除。不保证系统强制终止 App 后继续传输。
- 网易云手动下载可复用完整缓存并通过原有标签、歌词与本地音乐库提交流程保存，成功后去掉自动缓存副本。DizzyLab 的显式下载仍是官方专辑 ZIP，不用单曲串流缓存拼装或替代整张专辑包。
- iOS 设置与 macOS 播放设置中提供缓存占用和清理。清理取消离开歌曲的任务、阻止清理前的在途任务重新写回索引；当前播放器仍可读正在使用的文件，切歌后释放。手动下载、音乐库文件不受影响。占用显示完整缓存文件，不包含当前传输的暂存文件。
- 顺序下载支持从已接收区间即时读取；跳转到尚未收到的位置需要等待下载抵达该位置。请求合并、Range 分段续传不在本次实现范围。
