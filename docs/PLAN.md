# NeoDizzy 规划

记录于 2026-09-26，前期规划阶段确定的方向与分阶段目标。网站接口细节见 [SITE_API.md](SITE_API.md)。

## 1. 已确定的决定

| 项目 | 决定 |
| --- | --- |
| 形态 | 独立 App，不与 MeloX 合并；需要的代码按模块移植 |
| 分发 | 开源到 GitHub，用户自行侧载；不上架 App Store |
| 许可证 | GPLv3（移植 MeloX 代码的前提） |
| 工程 | XcodeGen + 同步文件夹 + 单元测试 Target；并发设置与 MeloX 相同（Swift 5 模式、默认 MainActor 隔离） |
| 设备 | 先只支持 iPhone、竖屏 |
| 视觉 | 外观可选跟随系统、浅色、深色（深色沿用 DizzyLab 品牌色）；主题色默认 DizzyLab 金色，可换色，桌面图标同步换色并随系统深浅切换 |
| 语言 | 界面只用简体中文（DizzyLab 是中文平台），不做其他语言 |
| 登录 | 原生账号密码表单，模拟提交网站的登录表单；不保存密码，只保存会话 |
| 购买 | 只做支付宝，支持自定价格（不低于最低价）、BOOST 和附言；不做 PayPal、购物车、兑换码、实体商品 |
| 下载 | 下载 ZIP 后解压到用户选择的文件夹，App 扫描该文件夹并离线播放 |
| 播放 | 只做基本播放和系统媒体控制；不做 AutoMix、均衡器、灵动岛、Apple Watch、歌词。被其他 App 打断后按系统建议决定是否续播（与 MeloX 一致） |
| 社区 | 点赞（+dB）与短评、repo 长评、随便听听、排行榜（网站只有按用户排名的支持者榜）、用户主页、关注社团 |

## 2. 界面结构

标签栏：发现、社团、关注、音乐库，加系统搜索标签。「我的」（账号、设置、关于）从各页页头右侧的头像按钮弹出，与 NeoBili 相同。

- **发现**：与网站首页相同的五个分段：数字专辑、单曲 EP、下载商品、pack、限时优惠。排行榜和随便听听的入口在 M5 加上。
- **社团**：全部社团；社团页展示作品并可关注。
- **关注**：已关注社团的新作动态（需登录）。
- **音乐库**：已购专辑，以及已下载到文件夹、可离线播放的专辑。
- **推入页面**：专辑、社团、用户主页、标签、pack、排行榜、随便听听（`AppRoute`）。

## 3. 架构

```
NeoDizzy/
├─ App/            入口、RootView（TabView + 每个标签独立的 NavigationStack）、MainTab、AppRoute
├─ Core/
│  ├─ UI/          配色（DizzyPalette）、页头、通用卡片
│  ├─ Networking/  DizzyHTTPClient（Cookie、csrf、Referer）、DizzyAPI（JSON 接口）、DizzyPages（HTML 解析）   M1
│  ├─ Models/      Disc / Track / Label / User，全部使用字符串 ID                                       M1
│  ├─ Playback/    精简版 PlayerStore、队列、恢复、NowPlayingSession（移植自 MeloX）                     M1
│  ├─ Account/     AccountStore + KeychainStore（参考 NeoBili）                                        M2
│  ├─ Downloads/   后台 URLSession 下载 → ZIP 解压 → 写入用户文件夹                                     M3
│  └─ OfflineLibrary/ 文件夹授权与扫描 + NeoDizzy 专辑曲目对应关系                                      M3
├─ Features/       各页面
└─ Resources/      图标、颜色等资源（界面文字直接写中文，不做本地化）
```

- **播放器**：MeloX 的 `PlayerStore` 与歌词、AutoMix 深度耦合，不直接照搬；新写精简版，只移植队列、恢复、系统媒体控制和播放页界面。
- **播放地址**：带时间签名，只在即将播放时获取，遇到 403 重新获取。
- **离线对应关系**：每张专辑解压后在目录里写 `.neodizzy.json`，记录专辑 ID 和曲目编号对应的文件，扫描时不依赖音频标签。
- **HTML 解析**：每个解析器配一份真实页面样本做单元测试，网站改版时能第一时间发现。
- **计划引入的依赖**：SwiftSoup（HTML 解析，M1）、Nuke（图片，M1）、ZIPFoundation（解压，M3）。

## 4. 关键流程

- **登录**：GET 登录页取 csrf → 带 Referer POST 账号密码 → 得到 `sessionid` → 从首页找到 `/u/<id>` → 从已购页取 API token → 会话和 token 存入钥匙串。会话失效时提示重新登录。
- **播放**：已下载的播放本地文件；否则用 token 请求专辑详情取播放地址。拿到的是试听片段时（长度各专辑不同），界面标明「试听」、显示试听长度，并提供购买入口。
- **购买**：原生面板选价格（+1/+5/+10/+50，实时显示 BOOST 百分比）和附言（≤100 字）→ 在注入会话 Cookie、使用 iPhone UA 的 WebView 里打开付款地址 → 进入支付宝 H5 收银台，`alipays://` 交给支付宝 App → 回到前台后轮询 `ihavethis` 确认到账。已购专辑的同一入口用于 BOOST。
- **下载**：下载前现取专辑页里的下载链接（1 小时有效）→ 后台下载 ZIP → 解压到「所选文件夹/社团/专辑」→ 写入对应关系文件 → 重新扫描。

## 6. 风险

- **没有官方 API**：网站改版可能让 HTML 解析失效。靠解析测试尽早发现，失效时降级显示并提供「在网页中打开」。
- **两套凭证**：网页用会话 Cookie，`/apis/` 用 token，可能分别失效，都要能检测并提示重新登录。token 不随退出登录失效，是长期凭据，只存在钥匙串里，日志里也要抹掉。
- **签名地址会过期**：播放地址和下载链接都要现用现取。
- **ZIP 文件名编码**：官方帮助提到含特殊字符的压缩包在 iOS 上可能打不开，需要按 GBK / Shift-JIS 尝试解码。
- **请求礼貌**：限制并发与频率、缓存列表数据，避免给网站造成负担。
- **开源发布**：仓库和安装包里不包含任何账号信息。

## 7. M3 实现与验收记录（2026-09-26）

代码已接入文件夹授权与 bookmark 恢复、下载格式选择、最多两张专辑并行处理、进度/取消/重新下载、后台 URLSession 事件桥接、ZIP 解压、`.neodizzy.json`、扫描和本地优先播放。下载任务保存专辑元数据与格式，不保存会话、token 或临时签名地址；启动任务与重试都重新读取专辑页。

导入先在隐藏目录中写齐文件与对应关系，再移动到「社团/专辑 [ID]」，不会覆盖用户已有目录。扫描只识别 NeoDizzy 对应关系文件；缺少音轨、同曲号多文件、重复专辑 ID 都明确报错。UTF-8 优先；GB18030 与 Shift-JIS 同时可解码时用已知曲名辅助选择，仍有歧义就停止导入。已下载目录提交后，即使取消或进程退出，也会以实际文件和索引重新核对任务状态。

自动验证使用人工构造的压缩包与临时文件夹，覆盖文件名编码、目录与符号链接越界、CRC 损坏、取消清理、曲目匹配、bookmark 恢复、本地播放地址优先和后台完成回调顺序。最终 `python3 scripts/test-core.py` 通过 87 项测试（13 组）；整个 App 和测试 Target 另通过 iOS `build-for-testing` 编译。

初轮开发时没有可用的 iOS 模拟器 runtime 和在线 iPhone。随后完成下述真机修复验证，M3 暂保留「已实现，待真机验收」，以下清单中其余后台与异常场景仍需验收：

- 用真实已购专辑分别下载 MP3 / FLAC，确认 ZIP 内文件名、目录和曲目对应关系。
- 选择「我的 iPhone」文件夹，退出重开 App 后确认授权仍有效；测试文件提供商撤销授权后的重新选择。
- 下载时锁屏或切换 App，确认系统后台下载、唤醒与导入状态；中断网络后重新下载确认链接刷新。
- 断网、退出账号后，从「已下载」播放、切歌并使用锁屏控制；移动或删除音轨后重新扫描。
- 在专辑写入完成前后取消下载、系统终止后重开，确认文件与任务状态一致。

云盘目录可以授权访问，但未保留设备副本的云文件不保证离线可用。系统后台会话的实际调度和被用户强制结束 App 后的行为，以 iOS 真机验收为准。

### 真机路径检查修复

在「我的 iPhone」文件夹下载时，导入曾错误提示存在不安全路径。根因是目标子目录尚不存在时，Foundation 可能保留父目录的别名，而检查用的根目录已解析为真实路径。现在先解析授权根目录，再逐级检查后代路径，文件操作继续使用授权 URL；真正外逃或断开的符号链接仍被拒绝。

修复新增 4 项回归，核心测试合计 91 项通过。在 iPhone 17 上使用 App 已登录会话实际下载「藏雪 - Snow Grave」（ALCD0001）的 FLAC ZIP，成功向原先选择的文件夹导入 5 首曲目，全部文件可定位，首曲通过 AVFoundation 可播放性检查（约 241.7 秒）。临时真机验收代码和音乐文件未写入仓库。此次验证不涵盖锁屏后台调度及网络中断重试。

## 8. M4 实现与验收记录（2026-09-26）

已接入数字专辑购买、免费领取和已购 BOOST：原生价格/附言面板，实时读取最低价和折后价，按整数分处理金额；首次购买显示相对折后价的 BOOST 百分比。追加 BOOST 页面没有公开累计基数，免费作品没有价格分母，因此这两种情况不虚构百分比。附言遵循网站 `maxlength=100` 的 UTF-16 长度限制。兑换商品和需要收货信息的实体商品不进入 App 收银台。

点击付款前重新核实账号、所有权和最新价格。收银台使用独立临时 WebKit 容器，在 Cookie 写入后仅加载一次，使用 iPhone UA，将 `alipays://` / `alipay://` 交给支付宝。关闭、异常和视图更新均不自动重新下单。收银台 URL、附言、token、Cookie 不写入付款记录。

回到前台、关闭收银台或手动核验时，最多轮询六次。首次购买确认从未拥有变成已拥有；BOOST 必须找到付款基线之后新增、账号/专辑/类型/金额匹配且创建时间有效的已付订单。网页跳转不是成功证据。未知页面、网络错误和延迟到账保留待核验，可在音乐库继续查询。账号切换会取消在途核验，按账号分别保留待确认元数据；停止跟踪不会取消网站订单。成功后刷新已购库、详情、下载权限和当前试听音轨。

自动测试覆盖普通/优惠/免费/BOOST 价格、金额边界、中文与特殊字符附言、兑换/实体商品拒绝、过期会话、收银台导航与 Cookie 范围、历史购物车订单、错误到账证据、取消与账号切换、持久化恢复及并发核验去重。真机只读验证覆盖登录后的价格面板、网站订单读取和 WebKit 会话。

最终核心测试 133 项（17 组）通过，iPhone 17 上另有 4 项验收测试通过：普通购买与 BOOST 面板渲染、数字订单/空 BOOST 页解析、隔离 WebKit 的 Cookie 与 iPhone UA、付款通知后重新加载当前试听并保留暂停与进度。真机截图经过视觉核对，临时验收代码、原始账号页面和截图不加入仓库。

未在开发过程中创建真实订单、领取商品或支付。以下场景由用户在安装后的 iPhone 上验收：

- 普通购买与已购 BOOST 分别打开 H5 收银台并跳转支付宝，完成付款后返回 NeoDizzy。
- 确认到账后已购库、下载入口、正在试听的曲目更新；未付款关闭时保持待核验。
- 延迟到账和其他形式的订单；初轮只读样本为 BOOST 空列表，后续实际订单的解析修复见下。
- 未安装支付宝、收银台网络中断、付款途中关闭 App，以及重新登录后的继续核验。

### BOOST 核验与支付宝返回修复

真实 BOOST 付款暴露了订单编号差异：追加支持使用 `dizz_boost_<账号>_<专辑>_<时间>_<后缀>`，普通购买使用 `dizz_<账号>_<专辑>_<时间>_<后缀>`。旧代码无法识别 BOOST 创建时间，因而保留待核验。现在按类型分别解析，仍要求账号、专辑、金额、新订单和时间全部匹配。已使用付款前保存的真实待核验记录，在 iPhone 上成功确认对应已付款 BOOST；没有重新下单。

新增 `neodizzy-pay://safepay` 返回入口。对可识别的支付宝 SafePay 调起信封，仅修改来源 App scheme；对已有的外层 `MQPSourceAppScheme` 只修改该字段，不改订单串、金额、签名及网站回执地址。返回后关闭收银台、进入音乐库并重新核验，不信任回调里自报的成功状态。未知调起格式继续使用原链接，并提示需要手动回到 App，不能保证所有 H5 变体都自动回跳。

来源 App scheme 的用途参见[支付宝 H5 转 App 文档](https://developer.alibaba.com/docs/doc.htm?articleId=105695&docType=1&treeId=193)。本次未引入支付宝闭源 SDK；签名参数不由客户端重建。真实支付宝的完整回跳仍需在下一次正常付款时验收，不能用 App 自身回调测试替代。

修复后 145 项核心测试（18 组）通过。真机额外确认原始待核验记录与真实已付 BOOST 匹配，并通过系统打开回调 URL 实际唤起 NeoDizzy、进入根视图的核验路由。临时诊断数据与验收代码不加入仓库。

### 随便听听播放器选曲（2026-09-26）

随便听听使用独立模式，播放器、迷你播放器和系统媒体控制共用选曲逻辑：上一首直接返回历史，不受普通专辑的「超过 3 秒先回开头」规则影响；下一首请求新的随机曲目，回退后请求新曲目会替换前方历史分支。最多保存最近 200 首的元数据，播放地址不持久化。切换普通专辑、重新开始随机会话或切换账号时，取消未完成的随机请求；请求失败保留当前曲目，可重试。暂停状态保持，重新启动恢复模式和历史。

真机自动化覆盖历史回退、合并重复点击、失败重试、迟到结果隔离、请求中暂停及旧快照兼容；测试使用本地静音音频与模拟选曲，不消费真实随机接口。
